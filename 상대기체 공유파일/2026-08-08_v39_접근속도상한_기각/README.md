## 무엇을 바꿨나
`Task_LeadPredict.cpp` — 접근 중 속도가 330m/s를 넘으면 스로틀을 깎는다.

```cpp
const double APPROACH_CAP = 330.0;
if (mySpd > APPROACH_CAP) {
    double over = (mySpd - APPROACH_CAP) / 100.0;
    if (over > 1.0) over = 1.0;
    double u = 1.0 - over * 0.55;
    if (u < 0.45) u = 0.45;
    target = (float)u;
} else { target = 1.0f; }
```

## 왜 시도했나 (2026-08-06 가설)
> 원거리에서 `dvTarget=999`(무제한 접근)로 풀스로틀 → 496m/s → 요 변화율 0.6~5°/s
> → **선회반경 약 28km**. 10초에 5.7km를 이탈하고 복귀에 160초. **빠른 게 손해다.**

v36(코너속도 260→287) v37(스로틀 하한 0.55→0.15) v38(거리게이트 제거)이 모두
**아무 일도 일으키지 못하고** 기각된 뒤, 거리 조건 없이 속도만 보고 거는 형태로 재시도.

### 가설이 틀린 지점
"원거리 풀스로틀 = 손해"는 **절반만 맞다.** 속도는 **거리를 좁히는 유일한 수단**이기도 하다.
상시 상한을 걸면 선회 능력을 사는 대신 **폐쇄율을 판다.** 그 대가가 직진 표적전에서
13승2무 → **1승14무**로 나타났다. 표적이 직선으로만 나는데도 못 따라잡는다.

**28km 선회반경은 "돌아야 할 때"만 문제다.** 그러므로 감속은 상시가 아니라
**선회를 예측했을 때만** 걸어야 한다 — 즉 선회 필요를 미리 알아내는 것이 진짜 과제다.
거리·ATA·속도 같은 현재 상태만으로는 그 예측이 안 된다(v38이 `ataDeg>12`로 시도해 실패).

### 승리가 패배가 아니라 무승부로 바뀐 것의 의미
패는 4패로 **동일**하다. 즉 v39는 **더 안 맞는다**(방어는 유지). 다만 **끝내지 못한다.**
규정상 타임아웃은 HP 비교이므로 무승부는 예선에서 0.5점 — 승리 17개를 0.5점씩으로
바꾼 셈이다. [[가치 순서: 승리 > 준 데미지 > 무피격]]에 정면으로 어긋난다.
