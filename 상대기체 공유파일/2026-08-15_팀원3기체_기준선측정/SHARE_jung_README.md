# 우리 기체 공유본 — 4자 비교용

작성 2026-08-15. 한 대의 PC에서 4명 기체를 대결시키기 위한 꾸러미입니다.

## 들어 있는 것

| 파일 | 설명 |
|---|---|
| `AIP_jung.dll` | 우리 기체 (Release x64, v143) |
| `AIP_jung_b.dll` | 위와 **완전히 같은 파일**. 우리끼리 자가대전(ownship/target 양쪽)을 돌릴 때만 필요합니다. 다른 팀 기체와 붙일 때는 안 써도 됩니다. |
| `Rule_jung.xml` | `AIP_jung.dll`이 읽는 행동트리 |

셋 다 **시뮬레이터 작업디렉터리에 같이** 넣으면 됩니다.

## 🔴 다른 세 분도 반드시 이걸 해야 합니다

모든 팀의 DLL이 소스에 이렇게 박혀 있습니다.

```cpp
tree = Factory.createTreeFromFile("./Rule_mine.xml");
```

**상대경로 하드코딩**이라 DLL 위치가 아니라 **프로세스 작업디렉터리 하나**를 기준으로 찾습니다.
DLL을 각자 폴더에 나눠 넣어도 소용없습니다. 그래서 4명 DLL을 한 폴더에 넣으면
**넷 다 먼저 발견된 XML 하나를 읽습니다.**

- 노드 이름이 안 맞으면 `CreateBehaviorTree failed`로 터집니다 — 이건 운이 좋은 경우입니다.
- **이름이 우연히 맞으면 에러 없이 조용히 남의 트리로 싸웁니다.** 그 결과로 "누가 제일 센가"를
  결정하게 됩니다. 우리는 다른 팀 DLL로 이미 이 현상을 겪었습니다.

그래서 **각자 한 줄 고치고 재빌드**해 주세요. 1인당 5분입니다.

```cpp
tree = Factory.createTreeFromFile("./Rule_<자기이름>.xml");
```

XML 파일명도 똑같이 바꾸고 `Configuration=Release / Platform=x64 / PlatformToolset=v143`으로 빌드.
DLL 이름도 `AIP_<자기이름>.dll`로 구분해 주세요. 이러면 4개가 한 폴더에서 공존합니다.

### 제대로 됐는지 확인하는 법

DLL 안에 박힌 문자열을 직접 봅니다. 자기 XML 이름이 나와야 합니다.

```bash
python -c "import re,sys; d=open(sys.argv[1],'rb').read(); print(sorted({m.group().decode() for m in re.finditer(rb'[\x20-\x7e]{4,}',d) if b'.xml' in m.group().lower()}))" AIP_jung.dll
```

우리 것은 이렇게 나옵니다.

```
['./Rule_jung.xml']
```

## 실행 환경

`AIP_jung.dll` 의존성은 `MSVCP140.dll` / `VCRUNTIME140.dll` / `VCRUNTIME140_1.dll` +
`api-ms-win-crt-*` 뿐입니다. **Debug CRT 의존성 없습니다** — VC++ 2015-2022 재배포 패키지만
깔려 있으면 Visual Studio 없는 PC에서도 돕니다.
(우리가 예전에 Debug CRT가 섞여 제출 불가였던 적이 있어 매번 확인하고 있습니다.
 각자 빌드도 이 확인을 한 번씩 해보시길 권합니다.)

## ⚠️ 순위를 매기기 전에 합의할 것 두 가지

**1. 채점기를 하나로 통일해야 합니다.**
저희 쪽 검증에서 로컬 채점기가 **뷰어가 주지 않는 Phase 2/3 데미지를 주고 있었습니다.**
저희 기체 점수의 최대 40%가 실서버에 없는 점수였습니다(08-13 실서버 4판으로 확인).
각자 자기 채점기로 낸 숫자를 들고 와 비교하면 자로 재는 게 아니라 **네 개의 다른 자를**
비교하는 셈입니다. 한 대의 PC에서, 하나의 채점기로, 같은 시드로 전부 다시 재야 합니다.

참고로 **주최측에 아직 문의 중인 사항**이 있습니다 — 대회 서버도 뷰어처럼 Phase 1만
적용하는지. 답에 따라 순위가 통째로 바뀔 수 있습니다.

**2. 판정 기준은 결과를 보기 전에 정해야 합니다.**
저희는 **평균이 아니라 상대별 최저값**으로 판정합니다. 대회는 토너먼트라 평균 1등이
특정 상대에게 0점이면 거기서 끝나기 때문입니다.
그리고 4자 대결 순위만으로는 부족합니다 — 대회 상대는 우리 넷이 아니고, 넷 사이에
가위바위보가 나오면 순위 자체가 의미를 잃습니다. **공통 상대 패널**에 각자 붙여서
최저값을 비교하는 쪽이 대회 조건에 가깝습니다.

기준을 먼저 정해야 하는 실질적인 이유가 하나 더 있습니다. 결과를 보고 정하면 각자
**자기 기체가 1등 되는 기준**을 주장하게 되고, 그게 모인 자리에서 제일 시간이 아깝습니다.
