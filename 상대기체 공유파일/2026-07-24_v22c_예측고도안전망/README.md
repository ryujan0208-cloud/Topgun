# v22c — 예측 고도 안전망 (고도추락 완전 해결, 채택 판단 대기)

## 문제 여정 (v22 → v22b → v22c)
규정 제6조: 우리 고도<300m = HP무관 즉시 패배. v21이 seed11에서 298m 추락 → 규정상 1패.
- **v22**(LeadPredict에 안전망 2단): 고도는 막았으나 하향억제가 조준 교란 → dealt 5.03→2.23 폭락.
- **v22b**(안전망 ① 제거, ② 강화): v21과 bit-identical. **안전망을 LeadPredict에 넣은 게 무의미**
  했음이 판명 — 트리 구조상 고도<1800이면 ClimbOut이 최우선이라 LeadPredict가 실행 안 됨.
- **v22c(채택 후보)**: 진짜 원인은 트리 최상위 **ClimbOut이 (a)늦게 (b)스로틀 없이** 발동한 것.
  seed11 실측: pitch −79°로 급강하, 1800선 도달 시 이미 pitch −88°(수직낙하)+모멘텀으로
  1461m 더 잃고 추락. 3파일 수정:
  1. `DECO_AltitudeCheck`: **예측형** — 하강률로 5초 후 예측고도<1800이면 발동(급강하 조기감지).
     수평비행(zdot≈0)엔 기존과 동일 = 교전 방해 없음.
  2. `Task_ClimbOut`: **풀스로틀** 추가(직전 근접전 낮은 스로틀이 상승력 부족의 원인).
  3. `Task_LeadPredict`: 죽은 안전망 제거.

상대가 뒤를 잡고 급강하하며 지속 사격 = **머지 각도전 패배**. P3의 "공격형 취약"과 동일 문제.
