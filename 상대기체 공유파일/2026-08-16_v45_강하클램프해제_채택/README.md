# ★★ v45 채택 — 강하 클램프 해제 (하강나선을 쓸 수 있게) · 2026-08-16

**v44(좌표 버그 두 곳 수정) 위에 성능 개선 하나를 얹었다.** 트리(XML)는 v42 이후 그대로다.
바뀐 것은 `Task_LeadPredict`의 강하 조준 클램프 두 줄뿐이다.

## 무엇을 바꿨나

```cpp
// 이전 (v18~v44)
double diveSlope = dist * 0.5;                 // 강하각 상한 약 27도
double diveCap   = 650.0;

// v45 (기본값)
if (!Ablation::off("v45dive")) diveSlope = dist * 3.0;   // 상승과 대칭
double diveCap = (!Ablation::off("v45dive")) ? 2000.0 : 650.0;
```

되돌리려면 절제 플래그 `v45dive` 하나로 v18 값으로 복귀한다.

## 왜 이제 되나 — 기각 조건이 사라졌다

v40 시절 같은 변경(`divefree`)이 **4승→1승으로 기각**됐다. 당시 기각 사유:

> 조준만 내리고 **벽은 그대로** = 최악의 조합

| 벽 | 기각 당시 | 현재 |
|---|---|---|
| `DECO_AltitudeCheck MinAlt` | **1800 m** | **700 m** (v42) |
| 조준 절대 하한 | **1500 m 고정** | **800~1500 m 동적** (v40) |

**두 벽이 다 내려갔다.** CLAUDE.md의 "반쪽 수정 금지"가 이 경우엔 반대로 작동했다 —
나머지 반쪽이 v40·v42에서 채워졌고, 이제 이 변경이 제 몫을 한다.

## 메커니즘

`diveSlope = dist * 0.5`는 강하각을 약 **27도**로 묶어 **하강나선 기하에 들어갈 수가 없었다.**

| 기동 (뱅크) | 지속 선회율 | 반경 |
|---|---|---|
| 수평선회 (82도) | 11.3 도/s | 1007 m |
| **하강나선 (110도)** | **25.4 도/s** | **493 m** |

우리 실전 지속 선회율이 **13~15.6 도/s = 수평선회 수준**이던 이유가 이것이다.
yuno가 강요하는 LOS 각속도는 600~900m에서 **16.1~17.4 도/s**라 하강나선이면 추종 가능하다.

**대가(156도 되돌리기당 고도 1967m)를 우리만 낼 수 있다:**
우리 700 / jung·jh2 800·1500 / yuno 1800·3200 / TW 3000.
