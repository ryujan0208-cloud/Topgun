## 🔴 버그는 **두 곳**입니다 — 이게 핵심입니다

| 진입점 | 위치 | 증상 |
|---|---|---|
| `Step` / `StepWithPlaneData` | `CPPBehaviorTree.cpp` | 서버 경로에서 거리가 `1.05e+08 m` |
| **`GetStick`** | **`LibMain.cpp:297`** | **위치는 변환, VP는 미변환 → 두 인자가 다른 좌표계** |

**둘 다 같은 원인**입니다. `LLAtoCartesian`을 이미 Cartesian인 값에 또 겁니다.
미터를 도(degree)로 읽으니 좌표가 무너집니다.

**`Step`만 고치면 `GetStick`을 부르는 하네스에서 여전히 눈이 멉니다.**
어느 쪽이 호출되는지는 하네스마다 다릅니다 — 파이썬 파이프라인은 `Step`을 부르고,
`GetStick`을 부르는 하네스도 있습니다. **머신 차이가 아니라 호출 경로 차이입니다.**

## 근거 — 주최측 답변 (2026-05-25)

VAIkyrie/이찬율님이 헤더 주석과 코드의 모순을 지적했고 운영측(codemist)이 답했습니다.

> `Vector3 Mylocation_Cartesian = LLAtoCartesian(MyInfo.Location, Vector3(OriLAT, OriLOn, 0));`
> … **이 부분은 지워야 했는데 까먹고 안지운 부분입니다.**
> … **송신은 Cartesian 좌표계로만 이뤄지며 LLA 좌표계는 무시하시면 됩니다.**

**그 줄이 `Step()`에도 `GetStick()`에도 있었습니다.** 한 곳만 고치면 반쪽입니다.

### 단위는 미터입니다 (피트 아님)

- 고도 `4572.0` ÷ 0.3048 = **정확히 15,000 ft**
- 이격 `608.5` — 규정 초기 거리 **610~914 m**. 피트면 185m로 안 맞음
- 속도 `200` — m/s면 정상, ft/s면 61 m/s로 F-16이 못 남

설계값은 피트로 떨어지는데 **전달은 미터**입니다(사거리 152.4~914.4 m = 500~3000 ft와 같은 패턴).

## 고친 방법 — 변환을 **한 곳으로** 모음

판별식이나 조건 분기를 쓰지 않았습니다. **진입점마다 판별식을 넣는 방식은
진입점이 늘 때마다 같은 실수를 반복합니다** (실제로 `Step`만 고친 v43이 `GetStick`을 놓쳤습니다).

| 진입점 | v44 |
|---|---|
| `ChangeData()` | LLA → Cartesian **변환 (유일한 변환 지점)** |
| `Step` / `StepWithPlaneData` | 변환 없음 — 항상 Cartesian을 받음 |
| `GetStick` | 변환 없음 — 항상 Cartesian을 받음 |
| 서버 경로 | 이미 Cartesian → 그대로 |

`oNavigationData`는 **정의상 LLA**(스케일 정수 `Lat=37923601`)라
`ChangeData`에서 변환해도 **이중 변환이 구조적으로 불가능**합니다.

⚠ 이 설계에서는 `Step`에 LLA를 직접 넣던 진단 스크립트가 깨집니다.
조용히 틀리는 게 아니라 **요란하게 깨지므로** 오히려 안전합니다.

### ③ 로컬 회귀 — **시드일치 10/45. 예상이 빗나갔다** ⚠

"변환의 위치만 옮겼고 수식·원점이 같으니 결과도 같아야 한다"고 봤는데 **틀렸습니다.**

**원인: `oPlaneData.Location`이 `float`(32비트)라 무엇을 담느냐로 정밀도가 달라집니다.**

| 저장되는 값 | float32 해상도(ULP) |
|---|---|
| 위도 37.914557° | **0.42 m** |
| **경도 128.181881°** | **1.34 m** |
| 직교 25,000 m | **0.002 m** |

- **v42**: `ChangeData`가 **LLA를 float32에** 넣음 → 위치가 **약 1.3 m 격자**로 양자화
- **v44**: `ChangeData`가 **직교 미터를 float32에** 넣음 → 약 **0.002 m**

**같은 수식도 어느 자료형을 거치느냐로 결과가 달라집니다.** 200초 교전에서 1.3 m 초기
오차가 증폭돼 궤적이 갈라집니다. v44가 **수백 배 정확**하며, 대회 서버가 보내는 것도
직교 float32이므로 **v44 쪽이 대회 조건에 더 가깝습니다.**

```

최대 1판 제외      +0.691    <- 부호가 뒤집힌다 = 분산의 신호
```

**차이는 전부 이미 50:50인 yuno 매치업에 몰려 있습니다. 퇴행이 아니라 주사위를
다시 굴린 것입니다.**

#### ⚠ 남는 의미

v0~v42의 모든 로컬 측정은 **대회에 존재하지 않는 1.3 m 위치 잡음** 위에서 이뤄졌습니다.
효과 크기가 컸던 결론(v40 고도하한, v41 Evade 제거, v42 ClimbOut)은 흔들리지 않지만,
**근소한 판정은 다시 봐야 합니다.** 그리고 **앞으로의 비교는 v44 기준으로 재측정**해야 합니다.
