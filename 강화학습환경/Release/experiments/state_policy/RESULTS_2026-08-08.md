## What the data supports

1. Offensive and defensive future windows occupy strongly different relative
   geometry. Onecircle and the sync sequence separate especially cleanly by
   own/target ATA.
2. Kwon damage windows are a distinct tail-chase regime: own ATA is near zero,
   target ATA is near 180 degrees, and headings are nearly aligned.
3. Speed regime matters. The sync-sequence dealt windows occur near 121 m/s,
   while taken windows occur near 332 m/s. This is evidence to analyze, not yet
   a command to slow down; causal direction is unknown.
4. One global maneuver or threshold is unlikely to represent all supported
   regions without regressions.

## What the data does not support

1. These are trajectories generated by v32, so the reports estimate
   observational exposure, not counterfactual action value.
2. A 10-second label is too broad for a direct BT trigger. Jink's median own
   ATA is 68 degrees even though the eventual damage must occur near the firing
   cone; geometry changes substantially within the horizon.
3. Overlapping windows exaggerate long engagements. Event bursts must be
   grouped before comparing frequencies.
4. The four-episode `sync-sequence` artifact must not be treated as the full
   15-seed sync baseline until an explicit run manifest confirms its origin.

## Prefix replay feasibility audit

Exact mid-flight checkpoint/restore is not currently available:

- `buildSerializedStatusSnapshot` stores only each BT node UID and status and
  has no corresponding restore operation;
- `JSBSimAIPLib.dll` exposes create/reset/init/run/get-data, but no flight-state
  restore entry point;
- `FighterSim.set_fdm_data()` changes a Python-side output structure, not the
  underlying native FDM; and
- v32 carries additional state in the controller error history, blackboard,
  BT nodes, and static maneuver histories/timers.

Initializing a new fight from a CSV position, attitude, and speed would
therefore be an approximate scenario, not the same scene.

Deterministic full-prefix replay is viable. ACE seed 0 was run three times with
the same v32 DLL, 10 Hz emulation, and configuration. Every run produced
`reward=342.1294`, dealt `0.0319`, and taken `0.0045`. More importantly, the
three paired tracks were byte-identical:

| Track | SHA-256 (all three runs) |
|---|---|
| ownship | `DF61EDD0F14DC13B36A18FF3E1B8FBC594DB2F371F0EE77EC572C456B6075D8E` |
| target | `C027AE5C0CC30620D4CB3ABEF443532F22AD9446AE0E63DB4BF8F8AA1DFBC664` |

Stamps were `2026_8_8_1_28_18`, `2026_8_8_1_29_32`, and
`2026_8_8_1_30_42` in the isolated Codex worktree.

A preliminary kwon replay correctly failed before flight because the copied
DLL loads `./Rule_mine.xml`, while the current tracked XML belongs to a newer
team-aircraft revision and requests a node absent from that DLL. This is a
paired-artifact provenance failure, not a flight result; future manifests must
record both DLL and XML hashes.

## Next milestone

The lab-only matched-prefix fork is now implemented. It adds an optional native
`StepWithVPOverride` export while leaving the ordinary `Step` path unchanged.
The BT still ticks, BT throttle is preserved, the production 75-degree VP clamp
still applies, and the stateful controller is called exactly once per update.
Legacy DLL loading remains compatible: the Python wrapper treats the new export
as optional.

### Normal-path regression

The lab DLL with override disabled produced stamp `2026_8_8_1_46_40`. Its
ownship and target CSV hashes exactly matched all three earlier unmodified v32
runs (`DF61...5D8E` and `C027...664`). Thus adding the dormant hook did not
change baseline behavior.

### First single-scene causal probe

The baseline ACE seed-0 trajectory dealt its largest damage burst starting at
154.7833 seconds. A `pure` VP override was applied from the first 10 Hz update
at 152.8167 through 155.7167 seconds (30 updates). The requested boundary was
152.75 seconds.

| Metric | v32 baseline | Pure VP fork | Difference |
|---|---:|---:|---:|
| Reward | 342.1294 | 382.0439 | +39.9145 |
| Dealt HP | 0.031866 | 0.046561 | +0.014695 |
| Taken HP | 0.004537 | 0.004537 | 0 |
| Net HP | +0.027330 | +0.042024 | +0.014695 |

The candidate's primary burst was 0.034285 HP versus 0.019833 in baseline. A
later burst was also larger (0.011561 versus 0.008420), while the baseline's
final 0.002898 burst disappeared. Therefore the reported total includes all
downstream consequences, not only the targeted burst.

`prefix_compare.py` verified 9,165 identical pre-fork rows for both aircraft.
The first ownship difference appeared at 152.8333 seconds and the first target
difference at 153.15 seconds, after the override began. This is a valid causal
fork of that one deterministic trajectory.

This result is **not a deployment decision**. It establishes one positive local
action sample for one ACE state. The next milestone is to repeat baseline and
candidate forks over multiple event anchors, then hold out seeds and opponents.
Only state regions with repeated positive net-HP effects, acceptable floor
margin, and no concentrated single-seed contribution may become BT branches.
