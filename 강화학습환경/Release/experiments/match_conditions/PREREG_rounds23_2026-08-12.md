# 사전등록 — 라운드 2·3 거리 검증 (v41 vs v40) · 2026-08-12

**결과를 보기 전에 작성한다.**

## 왜 필요한가 — 커버리지 공백

`rehearsal_10hz.py`는 초기 거리를 **시드로** 정한다:
```python
sep_m = MATCH_RANGES_FT[seed % 3] * FT     # 2000/2500/3000ft = 610/762/914m = 라운드 1/2/3
```
그동안 쓴 시드가 전부 **3의 배수**(0,3,…,42)라 `seed % 3 == 0` → **항상 라운드1(610m)**이었다.
로그 실측으로 확인: v41 비퇴행 배치 60판이 `round1 sep=610m` 100%.

즉 **v41은 세 라운드 거리 중 하나에서만 검증됐다.** 대회는 셋을 다 쓴다.
(사전등록 `PREREG_2026-08-11_rev2.md`가 "N2000 고정"이라 한 것은 축 분리 의도였고,
 그 자체는 잘못이 아니다. 문제는 **나머지 둘을 아직 안 메운 채 채택했다**는 것이다.)

## 실험

| | 값 |
|---|---|
| 시드 | **라운드2 = 1,4,7,…,43** / **라운드3 = 2,5,8,…,44** (각 15시드, cold) |
| 기하 | HABFM / OBFM_BLUE / OBFM_RED 전부 |
| 상대 | `AIP_jh2.dll` (최강 상대 1종으로 좁힌다 — 시드 예산) |
| 버전 | **v41**(`Rule_noevade.xml`)과 **v40**(기본) 둘 다, 같은 시드 |
| 규모 | 2거리 × 3기하 × 2버전 × 15시드 = **180판** |

⚠ ACE를 뺀 것은 시드 예산 때문이다. 마감(8/23)까지 11일이고, 지금 답해야 할 질문은
   "**v41 우위가 더 먼 시작 거리에서도 유지되는가**"이지 절대 성적표가 아니다.
   jh2는 우리를 가장 잘 이기는 상대이므로 퇴행이 나온다면 거기서 먼저 나온다.

## 판정 기준 (결과 보기 전에 고정)

**주 기준**: 각 (거리 × 기하) 셀에서 **v41 패 ≤ v40 패**.
  한 셀이라도 v41 패가 **+2 이상** 늘면 → **v41 재검토**(즉시 되돌림은 아님).
**보조**: 6셀 합계(90판)에서 v41 승 ≥ v40 승.
**안전**: 우리 추락(<300m) **0건 유지**. 1건이라도 나오면 원인 규명 전까지 채택 보류.

## 미리 적는 예측

- **v41 우위는 거리가 멀어질수록 줄어들 것이다.** Evade 게이트는 `거리<1100m`인데
  시작 거리가 610 → 914m로 멀어지면 개전 직후 게이트가 열릴 여지가 줄기 때문이다.
  즉 v40의 최대 약점(개전 2초 이탈)이 원거리에서는 덜 발동한다.
- 그래도 **퇴행은 없을 것**으로 본다. Evade는 legacy 5km 시작에서도 제거가 이득이었다
  (10상대 중 퇴행 0). 게이트가 늦게 열릴 뿐 열리면 같은 문제가 난다.
- **OBFM_RED가 여전히 최약 셀**일 것이다.

⚠ 빗나가면 그대로 적는다. 오늘만 예측이 네 번 중 세 번 빗나갔다.

## 함정 점검

- 시드를 3의 배수로 쓰지 않는다(이번 공백의 원인).
- 로그의 `round{n} sep={d}m`을 **실제로 세어** 의도한 거리가 나왔는지 확인한다.
- 배치가 도는 중 `ls -t`로 트랙을 집지 않는다.
- 상대 초기화 실패 시 파이썬이 죽는다 → **판수를 세어** 15판인지 확인한다.
