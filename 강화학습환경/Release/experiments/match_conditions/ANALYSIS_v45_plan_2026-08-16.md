# v45 설계 검토 — 전략 2건 + v44 전면 검산 · 2026-08-16

사용자 제안 2건을 **전제부터 측정**하고, v44 전반을 다시 훑었다.
오늘만 리드 가설이 반증됐고 회귀 예측이 빗나갔으므로 **먼저 재고 판단한다**.

## 전략 1 — "사거리 안에서 한 틱이라도 맞히기"

### 제안
사거리에 들어오면 순간적으로라도 VP를 상대 현재 위치에 정확히 꽂아 조금이라도 깎는다.

### ❌ 전제는 이미 반증돼 있었다
`tools_diag/lead_bias.py` 실측: yuno전 **99.2% 틱에서 우리 기수는 이미 상대 현재 위치에
더 가깝다.** 리드로 놓친 틱 0. **"VP를 상대에 꽂는다"는 이미 하고 있다.**

### ✅ 그런데 진짜 병목이 드러났고, 제안의 취지는 살아 있다

사거리(152.4~914.4m) **안에서만** 잰 각도:

| | vs yuno (짐) | vs jung (이김) |
|---|---|---|
| 판별 최소 ATA 중앙 | **7.65°** | **0.12°** |
| ≤1° (득점) | **0틱** | 1151틱 |
| 1~2° | **9틱** | 1140틱 |
| 2~3° | **20틱** | 1349틱 |
| >3° | 17,980 (99.8%) | 21,628 |

**우리는 2°에서 1°를 못 넘기는 게 아니라 7.65°에 있다.** VP를 정확히 꽂는 것만으로는
7.65°가 안 좁혀진다. 제안을 그대로 구현하면 효과가 없다.

**다만 1~3° 밴드에 이미 29틱이 있다.** 그리고 yuno전 15판 중 **7판이 1.0000 대 1.0000**
(양쪽 데미지 0)이었다. **1틱만 전환해도 무승부가 승리가 된다.**
→ 3승 7무 5패 → 최대 **10승 0무 5패**. 이번 캠페인에서 가장 큰 단일 이득이다.

### ★★★ 왜 마지막 1~3°가 안 좁혀지나 — 원인 규명

`Geometry/Controller_CY.cpp:183`

```cpp
ERROR_Effect = clamp(LOS/6 + clamp(GetLOSErrorSUM(LOS)/7.5, 0, 0.25), 0, 1.5);
PitchCMD     = ERROR_Effect * Roll_Effect * Horizon_Effect * (-1);
```

**피치 제어 권한이 `LOS/6`에 정비례한다.**

| LOS | 피치 권한 |
|---|---|
| ≥6° | 100% (포화) |
| 3° | 50% |
| **1°** | **17%** |

가까워질수록 조종 권한이 줄어드는 **순수 P 제어**다. 점근 수렴이라 움직이는 표적에는
마지막 각을 못 붙인다. 정상상태 오차를 지울 적분항은

- `clamp(..., 0, 0.25)` 로 **상한이 작고**
- `LOS ≤ 10°`일 때만 채워지는 **60샘플 평균**이며
- `ACTION_REPEAT=6`(10Hz)에서 60샘플 = **6초 지연**

**jung전은 안정 추적 구간이 길어 적분이 쌓여 0.12°까지 간다. yuno전은 창이 짧아
못 쌓이고 7.65°에서 멈춘다.** 두 매치업의 차이가 이걸로 설명된다.

### 설계 — 제어기를 건드리지 않고 BT에서 푼다

⚠ `Controller_CY::GetStick`은 제출 제약이다("BT는 VP만 설정한다"). 고치지 않는다.

**대신 LOS를 BT가 만든다는 점을 쓴다.** LOS는 기수와 **VP** 사이 각이다.
표적이 2° 벗어나 있을 때 VP를 **같은 방향으로 6° 이상** 밀어 두면 제어기는 포화 권한을
쓰고, 우리는 표적을 **지나치며 통과**한다. 콘에 머무는 대신 **콘을 가로지른다.**

- 이건 yuno가 주석에 쓴 관찰과 같은 원리다("Pure의 처짐이 LOS 중심으로 진동하며
  주기적으로 원뿔을 통과").
- 우리 것은 **의도적**이라는 점만 다르다.

**게이트(엄격히)**: 사거리 안 AND ATA < 5° AND 접근 중. 그 밖에서는 절대 발동 금지
(추종 기하가 무너진 v25의 실패를 반복하지 않기 위해).

**측정**: 1~3° 밴드 틱수와 ≤1° 틱수. **jung/jh2에서 퇴행이 0이어야 채택.**

## 전략 2 — "급하강으로 상대 고도하한 착취"

### 제안
뒤를 잡혀 파훼 불가면 최대속도 급하강 → 상대가 자기 하한에 먼저 걸려 이탈 → 우리가 급상승해 반전.

### ✅ 전제 확인 — 상대 하한이 XML에 그대로 있다

| 기체 | 고도 하한 |
|---|---|
| **TW** | `MinAlt=3000` (**예측식**) |
| **yuno** | `FloorHard=1800` / `FloorSoft=3200` |
| jung | `FloorHard=800` / `FloorSoft=1500`, TTG 6.0s |
| jh2 | `FloorHard=800` / `FloorSoft=1500` |
| **우리 v42/v44** | **`MinAlt=700`** (예측식) |

**우리가 전원 중 가장 낮다.** yuno 대비 **1,100m**, TW 대비 **2,300m** 여유가 있다.
이건 특정 상대 튜닝이 아니라 **우리가 이미 가진 구조적 우위**다.

### 🔴 그런데 지금 코드로는 착취가 안 된다

우리 하한도 **예측식**이라 실효 하한 = `MinAlt + 5초치 하강량`:

| 속도 | 강하각 | 우리 실효 하한 | yuno(1800) 대비 |
|---|---|---|---|
| 250 m/s | 60° | **1,783 m** | 사실상 동일 |
| 300 m/s | 60° | **1,999 m** | **우리가 더 높다** |
| 350 m/s | 45° | **1,937 m** | **우리가 더 높다** |

**급하강할수록 우리 하한도 같이 올라간다.** 최대속도로 내리꽂으면 **상대보다 먼저**
기수를 채올린다. 제안의 핵심 전제가 현재 코드에서 성립하지 않는다.

### 설계 — 게이트된 예측항 축소

그 특수 상황에서만 예측 선행시간 `T`를 5.0s → 1.5s 정도로 줄인다(하한 자체는 유지).
250 m/s 60° 강하에서 실효 하한이 1,783m → **1,025m**가 되어 yuno보다 **775m 아래**로 간다.

⚠ **예측항을 없애면 안 된다.** v22c가 실제 추락(1800m에서 걸린 뒤 1,461m 더 손실)
때문에 넣은 것이다. 줄이되 남긴다. 그리고 **절대 하한**(예: 예측 무시 500m)을 함께 둔다.

### ⚠ 위험 — 작지 않다

1. **v41 교훈**: `Task_Evade` 제거 사유가 "근거리 6시의 정답은 이탈이 아니라 선회진입".
   급하강도 이탈의 일종이다. **게이트가 헐거우면 개전 2초에 열려 판을 버린다.**
   Evade 게이트는 상대 ATA 25°로 열렸고 그걸로 망했다. 훨씬 엄격해야 한다.
2. **속도 문제와 충돌**: 우리는 이미 종반 358 m/s로 싸워 선회율을 못 낸다(실서버 실측).
   급하강은 속도를 더 올린다. **바닥에서 급상승 전환이 실제로 되는지 미확인.**
3. **실서버 스크림의 상대는 최저 305m까지 갔다.** 하한이 없거나 매우 낮은 상대에게는
   이 전략이 **역효과**다(우리만 낮은 고도에서 에너지를 잃는다).

### 판정
**전제는 성립하나 현재 코드로는 작동하지 않는다.** 예측항 게이트 축소가 선행돼야 하고,
게이트 설계가 v41의 실패를 반복하지 않아야 한다. **전략 1보다 위험이 크고 이득이 불확실하다.**

## v44 전면 검산

| 항목 | 결과 |
|---|---|
| **C1 다른 이중변환** | ✅ 없음. `LLAtoCartesian` 호출은 `ChangeData` 한 곳뿐 |
| **C3 러더 정수 절삭** | ✅ **우리 코드는 `float MFsum`이다.** 팀원이 보고한 `int` 절삭은 우리에게 해당 없음 |
| **C5 수신 스레드 크래시** | 🔴 `_process_packet`이 `try` 밖. 잘린 패킷 하나로 수신 정지 |
| **C6 제출본 정합성** | 🔴 `AIP_final.dll` + `Rule_forTraining.xml`이 좌표 수정을 **안 담고 있다** |
| **C7 종반 속도** | ⚠ 실서버 358 m/s. 코너속도 문제가 실전에서 재현됨 |
| **C8 선회율 40% 미사용** | ⚠ 17.3 vs 42.8°/s. **여전히 최대 미규명 항목** |
| **C2 dt 버그** | ⚠ 미해결. 10Hz에서 상대 선회율 7~9배 오독 |

### ★ C8과 전략 1의 연결

`ERROR_Effect = LOS/6` 이 C8의 유력한 설명이다.
사거리 안 우리 ATA 중앙이 7.65°면 피치 권한은 **거의 포화(100%)** 여야 한다.
그런데 실측 선회율은 17.3°/s로 능력(42.8°/s)의 40%다.
→ **제어 권한이 아니라 다른 데서 막힌다.** 속도(코너속도)일 가능성이 높다.
→ **C7과 C8은 같은 문제일 수 있다.** 다음 조사 1순위.
