### ★ 상대별로 정반대다 — 이게 핵심이다

- **추격이 성립하는 상대**(jung·jh2, 우리가 뒤를 잡음) → 게이트 확대가 **이득**
- **각도 싸움 상대**(yuno, 서로 선회) → 게이트 확대가 **준데미지를 1/3로 무너뜨림**

`aim20`이 **합계로는 최고**(+0.935)지만 그 이득이 전부 이미 이기는 상대에서 나온다.
**정작 지고 있는 yuno에서 무너진다.**

**기각 근거 셋:**
1. 사전 고정 기준 — "어느 상대든 준데미지가 줄면 즉시 기각"
2. 대전제 — "어떤 기체일지 모르는 고도화된 상대를 이겨야 한다. 특정 상대 대응 튜닝 금지"
3. 상대별 최저값 판정(jung README 제안, 토너먼트 특성) — base가 모든 후보를 이긴다

### 왜 그런가 — 코드가 이미 답을 적어놨다

> 리드는 사격이 아니라 **추종 기하**를 위한 것이다.
> 순수 조준은 상대 선회 안쪽으로 못 파고들고 뒤로 밀린다(pure pursuit → overshoot).

v25가 같은 실패를 했고(dealt 4.34 → 1.53) 이번이 그 재현이다.
**추종이 필요 없는 상대에겐 리드가 덜 중요하고, 추종이 전부인 상대에겐 리드가 생명줄이다.**

**부수 확인: 현행 v27 게이트(10°)가 잘 고른 값이라는 것이 다섯 지점 측정으로 역증명됐다.**

## ② mergeslow — **판정 보류. 표본 부족.**

### 무엇을 고쳤나

```cpp
bool beingChased = (enemyAtaDeg < 35.0) && (dist < 2500.0);
bool needTurn = ... && (mySpd > CORNER + 30.0) && !beingChased;
```

**머지 접근 중 상대 ATA가 21~29°라 `beingChased`가 항상 참**이 되어 코너속도 감속이 차단된다.
원래 의도는 "적이 나를 겨누면 에너지를 지킨다"(방어 논리)지만,
**머지는 서로 겨누는 순간**이라 같은 규칙이 우리만 손해 보게 만든다.

```cpp
bool mergeNow = Ablation::sel("mergeslow") && (closeRate > 300.0) && (dist < 1600.0);
bool needTurn = ... && (!beingChased || mergeNow);
```

`closeRate`(접근속도)는 거리의 시간 변화로 직접 잰다. `dtEff`(위치차분 실측 틱간격)를 쓴다 —
`DeltaSecond`는 1/60에 고정돼 `ACTION_REPEAT=6`에서 6배 틀리기 때문이다.

### 결과 (vs yuno 15시드)

| | base | **mergeslow** |
|---|---|---|
| 성적 | 1승 9무 **5패** | **2승 10무 3패** |
| 순이득 | −0.449 | **+0.225** |
| 준데미지 | 0.215 | **0.426** |
| 받은 | 0.664 | **0.201** |
| 우리 추락 | 0 | **0** |

**오늘 처음으로 yuno전 순이득이 플러스가 됐다.**

### 🔴 그러나 분산 검사에서 걸린다

```
전체 순이득 변화   +0.674
최대 1판 제외      +0.265    <- 61% 감소
최대 2판 제외      +0.031    <- 사실상 0
```

발동은 15판 중 **4판(27%)** 뿐이고, 그 4판의 기제도 제각각이다:

| seed | 변화 | 내용 |
|---|---|---|
| 34 | **+0.409** | 받은 게 0.497 → 0.088 (**방어** 이득) |
| 43 | **+0.234** | 준 게 0 → 0.218 (**공격** 이득) |
| 13 | +0.038 | 미미 |
| 4 | −0.007 | 미미하게 손해 |

**seed 34 하나가 전체의 61%.** 판정원칙 3에 따르면 분산과 구분되지 않는다.

→ **독립 표본(새 시드 15개, `k*3+2`)으로 재확인 중.**
   사전 기준: 새 표본에서도 순이득 개선 AND 최대1판 제외 후 부호 유지.

## ③ 감속으로는 머지를 못 푼다 — 물리적으로 막혀 있다

`mergeslow`의 원래 가설은 "접근 450 m/s를 350으로 낮춰 창을 +29% 늘린다"였다. **틀렸다.**

**접근속도 450 m/s는 둘의 합이고 우리 몫은 절반이다.** 그리고 우리 속도는:

| | 중앙 | 290 m/s 초과 시간 |
|---|---|---|
| vs yuno | **226 m/s** | 8.4% |
| vs 기준모델 | **254 m/s** | 11.5% |

**우리는 이미 코너속도(260) 근처이거나 아래다.** 더 늦추면 선회율이 오히려 떨어진다
(200~225 구간 13.2°/s < 250~275 구간 15.6°/s).

**즉 `mergeslow`가 효과를 낸다면 그건 "감속으로 창을 늘려서"가 아니다.**
발동률 27%와 기제 불일치(방어/공격)를 보면 **작동 원리가 아직 규명되지 않았다.**
독립 표본에서 살아남더라도 **메커니즘을 설명하기 전에는 채택하지 않는다**(판정원칙 1).
